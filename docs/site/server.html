CH.08 · 服务端

GameFrameX.Server — 服务端概览

Server/ 是 GameFrameX.Server 的快照（.NET 10，Apache-2.0，来源见 Server/PROVENANCE.md）：Actor 模型（TPL DataFlow）+ SuperSocket 多协议 + MongoDB 持久化 + 状态-组件-代理三层与零停机热更新。本仓库的唯一增量是 Server/Config/（Luban 生成的我们自己的配置库）。

.NET 10 · C# MongoDB · SuperSocket · protobuf-net Roslyn 分析器强制分层（GFX0001~14）

1 核心模式：状态-组件-代理（State-Component-Agent）

Agent 方法的调度行为由特性标注控制——这是 Actor 串行化的关键：

特性调度行为
[Service]（默认）进入该 Agent 的 Actor 消息队列串行执行（TPL DataFlow 无锁排队，天然免锁）
[ThreadSafe]跳过队列直接调用（方法自身保证线程安全时用）
[Discard]即发即弃（不等待结果）
[TimeOut(ms)]方法级超时

Roslyn 源码生成器自动生成 Agent 的 Actor 消息队列调度代码（GameFrameX.Hotfix.WrapperGenerator）；Architecture.Analyzers 在编译期强制：State/Component 定义在 Apps 层、Handler/EventListener/ComponentAgent 定义在 Hotfix 层、命名后缀约定、Handler 必须 sealed（GFX0001~GFX0014）。

2 解决方案结构（7 个项目 + 我们的增量）

项目类型职责
GameFrameX.LauncherExe（net10.0）入口：Program.cs 注册状态类型与协议消息 → AppStartUpGame 启动流程（ActorLimit → GameDb(MongoDbService) → ComponentRegister → HotfixManager 加载热更程序集 → 主循环）。Debug 输出 bin/app_debug
GameFrameX.Appsclasslib状态层（不可热更）：ActorType、Account/Player(Player/Bag/Pet)/Server/Common 的 State + Component
GameFrameX.Hotfixclasslib热更层（可运行时替换）：各组件代理（ComponentAgent）、Http/Player/Account/Server Handler、StartUp 流程
GameFrameX.Hotfix.TestsxUnitHotfix 单元测试
GameFrameX.Configclasslib上游自带的配置系统：ConfigComponent + JSON 热加载（本地化/成就/物品/音效）
GameFrameX.Protoclasslib上游协议定义（Basic_10 / Bag_100 / User_300 等）
GameFrameX.Architecture.Analyzersnetstandard2.0 分析器编译期分层规则

两套配置系统并存（别混淆）

3 零停机热更新

# Hotfix 程序集发布到 hotfix/ 目录，由 HotfixManager 加载
# 运行时替换业务程序集（状态留在 Apps 层不受影响）：
curl "http://localhost:28080/game/api/Reload?version=1.0.1"

原理：State（持久化数据）在 Apps 层不动，业务逻辑（Agent/Handler）在 Hotfix 层整体替换；Docker 部署时 hotfix/ 与 json/ 是挂载卷（entrypoint.sh 在目录为空时拷入默认产物，见 Server/Dockerfile 多阶段构建）。

5 与客户端的对接面

[MessageHandler] 特性分发        ◄──推送──    Handler/Agent（Hotfix 层）

  TbServerList（07 章）预置 127.0.0.1:29100 = "本地开发服"（Normal）
  Protobuf/proto/module_demo.proto = demo 模块（HeartbeatReq/Resp、LoginReq/Resp、NoticeNotify）

监控与可观测：OpenTelemetry + Prometheus；对象映射 Mapster；雪花 ID、存盘批量策略等均由 AppSetting 环境变量控制（Server/docker-compose.yml 内有逐项中文注释）。
