CH.03 · 资源管理

Asset & YooAsset — 资源管线

资源链路是三层封装：业务代码注入 IAssetService（自研桥接）→ AssetComponent / AssetManager（GameFrameX asset 5.0，门面 + 补丁状态机）→ YooAsset 3.2.0（ResourcePackage / 文件系统 / 句柄引用计数）。本章讲清每一层的 API 与语义，重点是句柄生命周期——资源泄漏基本都出在这。

3 InitPackageAsync 流程拆解

public Task<bool> InitPackageAsync(string packageName, string hostServerURL, string fallbackHostServerURL, bool isDefaultPackage = false)
{
    var tcs = new TaskCompletionSource<bool>();
    var resourcePackage = YooAssets.TryGetPackage(packageName);
    if (resourcePackage == null)
    {
        resourcePackage = YooAssets.CreatePackage(packageName);
        if (isDefaultPackage) { YooAssets.SetDefaultPackage(resourcePackage); }
    }
    var initOp = CreateInitializationOperationHandler(resourcePackage, hostServerURL, fallbackHostServerURL);
    initOp.Completed += op =>
    {
        if (op.Error == null && op.Status == EOperationStatus.Succeed && op.IsDone)
            tcs.TrySetResult(true);
        else
            tcs.TrySetException(new Exception(op.Error));   // 自研层 ProcedurePatch 捕获后停留等待处理
    };
    return tcs.Task;
}

4 四种播放模式（EPlayMode）

本项目默认 编辑器模拟模式：无需真机 AB，直接按收集器配置在内存里"模拟构建"出清单，配合 EditorFileSystem 从 AssetDatabase 读资源。开发期日常使用。

// AssetManager.Initialization.cs
EditorSimulateModeHelper.SimulateBuild(nameof(EDefaultBuildPipeline.BuiltinBuildPipeline), "DefaultPackage")
// 参数：EditorSimulateModeParameters { EditorFileSystemParameters }

原理：编辑器下反射调用编辑器程序集 YooAsset.Editor.AssetBundleSimulateBuilder.SimulateBuild，按 Collector 配置生成 SimulateBuildResult 内存清单（非编辑器调用直接抛异常）。这意味着改收集器配置立即生效，不用打包。

注意：自研层 AssetService.InitializeAsync 在此模式下直接返回 true（GameFrameX 组件启动时已按 AssetOptions 完成初始化），避免重复初始化。

离线模式：单机/内置包，无热更。资源打进安装包，运行时从内置文件系统（StreamingAssets 相关目录）读取。

// 参数：OfflinePlayModeParameters { BuildinFileSystemParameters = CreateDefaultBuildinFileSystemParameters() }

适合：买断制单机、首包玩法完整、无补丁需求的场景。发布前需要真实构建 AB。

联机模式：热更主力。内置文件系统（首包资源）+ 缓存文件系统（下载的补丁资源，RemoteServices(host, fallback) 双地址）。

// 参数：HostPlayModeParameters {
//     BuildinFileSystemParameters,                                  // 首包内置
//     CacheFileSystemParameters = new RemoteServices(host, fallback) // CDN 主/备
// }
await asset.InitializeAsync(EPlayMode.HostPlayMode, hostUrl, fallbackHostUrl);
本项目 v0.1 边界

HostPlayMode 的完整补丁流（静态版本请求 → 清单更新 → 创建下载器 → 断点续传/重试）尚未在 IAssetService 封装；当前 InitializeAsync 只做包初始化。联调时可用任意静态 HTTP 服务挂 CDN 目录（地址填 GameFrameYLaunchSettings.HostUrl，或用配置表 TbGlobal.PatchUrl——本仓已预置 http://127.0.0.1:8080/CDN/...）。

补丁状态机（EPatchStates，asset 包已备好事件）：UpdateStaticVersion → UpdateManifest → CreateDownloader → DownloadWebFiles → PatchDone，配套 AssetPatchStatesChangeEventArgs 等 6 个事件参数。

WebGL 模式：资源在 Web 文件系统（远端目录直读，无本地缓存目录概念），AssetComponent.Awake 在 UNITY_WEBGL 下强制切到此模式。

// 参数：WebPlayModeParameters { WebFileSystemParameters = WebPlayModeFileSystemProviderRegistry.CreateFileSystemParameters(host, fallback) }

核心语义：每次 Load 得到一个句柄 = 一份引用；Release()（即 Dispose）把引用计数减一，归零才真正卸载底层 Provider。没 Release 会泄漏，Release 多次会提前炸掉别人的引用。

三条铁律
  • 一次 Load 配一次 Release。UnloadAssetHandle(object) 只认 AssetHandle 类型，传错类型静默忽略（不会报错！）。
  • ConfigService.LoadAsync 的正确示范：把全部表句柄收集进 List，finally 里统一释放——bytes 已进内存，句柄用完即走。
  • UI 框架内部自己管理句柄（openUIFormInfo.SetAssetHandle(assetHandle)），业务层不要对 UI prefab 手动 Load/Release。

6 YooAsset 收集器（Collector）与寻址

编辑器侧配置在 AssetBundleCollectorSetting.asset（菜单 YooAsset → Bundle Collector）：Package → Group → Collector 三级。Collector 指定 Assets 下的收集路径与规则：

  • 寻址规则（AddressRule）：本项目配置组用 AddressByFileName —— 定位地址 = 文件名去扩展名。所以 Assets/Bundles/Config/tbitem.bytes 的加载地址就是 "tbitem"，正好对上 ConfigService 的"表属性名小写"约定。
  • 其他内置规则：AddressDisable（禁用寻址）、AddressByGroupAndFileName、AddressByFolderAndFileName。
  • 包级开关：EnableAddressable / LocationToLower / IncludeAssetGUID / AutoCollectShaders / UniqueBundleName 与打包规则 PackRule、过滤规则 FilterRule、忽略规则 IgnoreRule。
已知坑（README 排障清单）

Luban 重新生成会重建 Bundles/Config 目录导致 目录 GUID 变化，Collector 窗口提示 CollectPath/GUID 不匹配：窗口里点 Fix，或把 AssetBundleCollectorSetting.asset 里 CollectorGUID 改为该文件夹 .meta 的 guid。EditorSimulate 下加载配置失败 → 确认 Config 组启用。
