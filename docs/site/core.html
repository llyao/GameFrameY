CH.01 · 自研核心层

GameFrameY.Core — 模块管理与服务发现

整个仓库的核心交付：com.gameframey.core（v0.1.0）用 VContainer 实现了模块自动发现 → 依赖拓扑排序 → 链式子作用域装配的模块体系，配合 IServiceRegistry 的两级服务发现，再把六个 GameFrameX 组件桥接成服务。本章逐文件拆解，并附两个可交互演示。

com.gameframey.core 0.1.0 依赖：VContainer 1.19 + UniTask 2.6 Runtime/Core + Runtime/Bridge 两个 asmdef

2.2 模块生命周期：IGameModule 与三个 Tick 接口

public interface IGameModule

    GameModuleDescriptor Descriptor { get; set; }   // 装配时由管理器回填

2.3 GameModuleBase：可选基类

public abstract class GameModuleBase : IGameModule
{

    [Inject]

    public virtual UniTask OnInitializeAsync() => UniTask.CompletedTask;
    public virtual UniTask OnStartAsync()      => UniTask.CompletedTask;
    public virtual UniTask OnShutdownAsync()   => UniTask.CompletedTask;

    // 登记为 TService，归属当前模块；模块卸载时自动注销
    protected void RegisterService<TService>(TService instance) where TService : class
    {
        Services?.Register(instance, Descriptor?.Name);
    }
}

2.4 自动发现：ModuleScanner

ModuleScanner.ScanModules(params Assembly[] assemblies)：参数为空时扫描 AppDomain.CurrentDomain.GetAssemblies()，否则只扫指定程序集（热更程序集加载后二次装配用）。过滤规则：

  • 程序集名以下列前缀开头即排除（忽略大小写）：System / mscornet / netstandard / Mono / Microsoft / Unity / UnityEngine / UnityEditor / JetBrains / nunit
  • ReflectionTypeLoadException 降级为已加载部分类型；其他反射异常跳过整个程序集
  • 类型筛选：非 abstract、非 interface、typeof(IGameModule).IsAssignableFrom(type)、带 GameModuleAttribute

2.5 依赖解析：ModuleDependencyResolver（DFS 拓扑排序）

排序算法（与源码一致）：

  1. 为每个类型建 GameModuleDescriptor，按名查重，重名抛异常；
  2. 种子序列 = OrderBy(Priority).ThenBy(Name, Ordinal)——注意是对全量模块排序（含 Deferred），阶段过滤发生在解析之后；
  3. 对每个种子做 DFS：先递归访问全部依赖（后序输出 ⇒ 依赖先装配），依赖缺失抛 "模块 {name} 声明的依赖 [{dep}] 未在扫描结果中找到"，遇到回边抛 "模块依赖成环: A -> B -> A"；
  4. 结果回写 InstallOrder。
源码级发现：v0.1 的环检测是死代码

ModuleDependencyResolver.Visit 里环检测写的是 if (visited.Contains(name)) { if (visiting.Contains(name)) throw 成环; return; }——但"正在访问中"的节点不在 visited（完成前不会加入），而完成时又会先 visiting.Remove 再 visited.Add，两个集合永不同时含同一名字。于是真正的依赖环不会触发友好报错，而是无限递归直到栈溢出。修法很简单：先查 visiting.Contains 抛环，再查 visited 返回。下方模拟器按修正后的语义实现（所以能给出漂亮的成环路径报错）。

2.6 装配与驱动：GameModuleManager

管理器本身是根容器的 VContainer EntryPoint（实现 ITickable / IFixedTickable / ILateTickable，挂 PlayerLoop，无需 MonoBehaviour）。装配核心两阶段：

// 阶段一（逐个交错：建作用域 + Init）
foreach (var descriptor in descriptors)
{
    var installer = CreateInstaller(descriptor);            // InstallerType + 模块类型本身包成 ModuleScopeInstaller
    var parent = _lastCreatedScope ?? _rootScope;           // ★ 链式作用域：以"上一个创建的作用域"为父
    var scope = parent.CreateChild(installer, $"GameFrameY.Module.{descriptor.Name}");
    var module = (IGameModule)scope.Container.Resolve(descriptor.ModuleType);
    await module.OnInitializeAsync();                        // 每装一个就 Init 一个
}
// 阶段二（同批按装配序串行启动）
foreach (var descriptor in _installed.Where(d => d.State == GameModuleState.Initialized))
{
    await descriptor.ModuleInstance.OnStartAsync();
    descriptor.State = GameModuleState.Started;
}
Runtime/Core/Module/GameModuleManager.cs（InstallCoreAsync 节选）——整体顺序：Init(M1)→…→Init(Mn)→Start(M1)→…→Start(Mn)

作用域链是本章最重要的架构约束：第 N 个模块的子作用域以第 N-1 个为父，形成 Root → M1 → M2 → … → Mn 线性链。VContainer 子作用域只能向上解析，因此模块能构造注入的 = 自己 Installer 注册的 + 声明过依赖的（保证在祖先链上）+ 根作用域的。未声明的跨模块引用在装配期即失败——依赖声明即保护。

真实装配顺序是怎么算出来的

InitializeBootstrapModulesAsync 先对全量扫描结果（含 Deferred 的 Demo）做一次 DFS 排序，然后才过滤出 Bootstrap 模块。全量种子按 Priority 升序，Demo(100) 排第一，DFS 访问它的依赖 [Config, Asset] 把 Asset → Config 拉到序列最前（Config 又依赖 Asset，先输出 Asset）；剩余 Bootstrap 模块按 Priority 依次输出。所以六个桥接模块的真实装配顺序是 Asset → Config → Network → UI → Scene → Event，Deferred 阶段 Demo 挂在 Event 的子作用域下。上方模拟器可以复现这条链。

其余职责：

  • Tick 泵：每帧遍历 _installed（装配序），仅 Started 且实现对应接口的模块收到回调；单模块异常捕获记日志不中断其他模块。
  • ShutdownAsync：逆序卸载——仅 Initialized/Started 状态才调 OnShutdownAsync（异常吞掉记日志）→ ServiceRegistry.UnregisterAll(模块名) 注销其登记的服务 → scope.Dispose()。
  • 幂等：InitializeBootstrapModulesAsync 有 _bootstrapInstalled 防重入；InstallDeferredModulesAsync 过滤已装配的。
  • Installer 包装：ModuleScopeInstaller 先 builder.Register(模块类型, 模块类型, Singleton)（模块实例由自己作用域创建），再执行业务 Installer。

3 服务发现（Core/Service）

IServiceRegistry 的两级查找语义：① 中央注册表——模块运行期 RegisterService(new Xxx()) 登记的实例（含归属模块、增删事件）；② 根容器兜底——各模块 Installer 注册的类型服务（VContainer TryResolve）。消费优先级：构造注入 > 服务定位（后者面向热更代码 / 场景对象 / 调试）。

API说明
event Action<ServiceChangeEventArgs> ServiceChangedAdded / Removed 变更事件（参数含 ServiceDescriptor）
Register<T>(T instance, string ownerModuleId = null)登记实例；类型校验 + ReferenceEquals 去重（重复静默返回）
TryGetService<T>(out T) / GetService<T>()两级查找；GetService 失败抛 ServiceRegistryException
GetServices<T>() / GetAllServices(Type)多实现聚合（中央表全部 + 容器 IEnumerable，按引用去重）
Unregister<T>(T) / UnregisterAll(ownerModuleId)注销；模块卸载时管理器自动调 UnregisterAll
UniTask<T> WaitServiceAsync<T>(CancellationToken)未就绪先等待：订阅 ServiceChanged 后二次检查防竞态，命中即完成

同类型多实例时中央表后登记者优先（list[list.Count-1]），便于覆盖。两个防御性设计值得记住：① WaitServiceAsync 订阅事件后立即再查一次（避免登记发生在"查"与"订阅"之间）；② 注册表仅设计为主线程使用。

5 启动编排（Startup → RootInstaller → Launcher → Procedures）

5.1 组合根三件套

// ① BeforeSceneLoad 建根作用域（无需场景摆放任何东西）
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
private static void Bootstrap()
{
    if (_rootCreated) return;
    _rootCreated = true;
    ConfigureGameFrameXOptions();   // 必须发生在组件首次消费前：AssetOptions/SceneOptions/ProcedureOptions
    var scope = LifetimeScope.Create(new GameFrameYRootInstaller(), "GameFrameY Root");
    Object.DontDestroyOnLoad(scope.gameObject);
}

// ② 根注册器：四件套
public void Install(IContainerBuilder builder)
{
    builder.Register<IServiceRegistry>(r => new ServiceRegistry(r), Lifetime.Singleton);
    builder.RegisterInstance(new GameFrameYLaunchSettings());
    builder.RegisterEntryPoint<GameModuleManager>(Lifetime.Singleton);        // Tick 泵
    builder.RegisterEntryPoint<GameFrameYGameLauncher>(Lifetime.Singleton);  // 启动协调器
}

// ③ 启动协调器（IAsyncStartable，首帧 Startup 时机执行）
public async UniTask StartAsync(CancellationToken cancellation)
{
    await UniTask.WaitUntil(IsGameFrameXReady, cancellationToken: cancellation);  // 等 AfterSceneLoad 的宿主
    await _modules.InitializeBootstrapModulesAsync();
    StartDefaultProcedures();   // ReinitializeProcedures + StartProcedure(Launch)
}

流程基类 GameFrameYProcedure 提供了 RunFlow 助手——在 FSM 的同步回调 OnEnter 里安全启动异步流程：

protected void RunFlow(Func<UniTask> flow)
{
    UniTask.Void(async () =>
    {
        try { await flow(); }
        catch (Exception e) { GfyLog.Error($"流程 {GetType().Name} 异步流程异常: {e}"); }  // 停留在当前流程
    });
}

事件常量目前只有一个：GameFrameYEventIds.GameReady = "GameFrameY.GameReady"。

6 参考实现：Demo 业务模块（全文 51 行）

位于 Assets/GameFrameY/Game/Modules/Demo/，一次演示三个能力——配置读取、动态服务登记与发现、Tick 心跳：

[GameModule("Demo", Startup = ModuleStartup.Deferred, Priority = 100,
            Dependencies = new[] { "Config", "Asset" })]
public sealed class DemoModule : GameModuleBase, ITickableModule
{
    private float _tickTimer;
    private int _tickCount;

    public override UniTask OnStartAsync()
    {
        var config = Services.GetService<IConfigService>();

        // 1) Luban 配置读取（YooAsset → bytes → cfg.Tables）
        var item = config.Tables.TbItem.GetOrDefault(10001);
        GfyLog.Info($"[Demo] TbItem[10001] = {item?.Name}（{item?.Desc}）价格 {item?.Price} 品质 {item?.Quality}；" +
                    $"TbGlobal.HotfixEnabled = {config.Tables.TbGlobal.HotfixEnabled}");

        // 2) 动态服务登记 → 其他模块可 WaitServiceAsync 发现
        RegisterService(new DemoGreetingService());
        var greeting = Services.GetService<IDemoGreetingService>().SayHello("GameFrameY");
        GfyLog.Info($"[Demo] {greeting}");
        return UniTask.CompletedTask;
    }

    public void OnTick(float elapseSeconds, float realElapseSeconds)
    {
        _tickTimer += realElapseSeconds;        // 用 unscaled 时间
        if (_tickTimer < 3f) return;
        _tickTimer = 0f;
        GfyLog.Info($"[Demo] Tick 心跳 #{++_tickCount}");   // 每 3 秒一条
    }
}

7 如何新增一个业务模块

最小模板（Shop 模块示例）
[GameModule("Shop", Startup = ModuleStartup.Deferred,
            Dependencies = new[] { "Config", "Asset", "UI" },
            InstallerType = typeof(ShopModuleInstaller))]
public sealed class ShopModule : GameModuleBase, ITickableModule
{
    public override UniTask OnStartAsync()
    {
        RegisterService(new ShopService());   // 动态登记，别处可 WaitServiceAsync
        return UniTask.CompletedTask;
    }
    public void OnTick(float dt, float rdt) { /* 每帧 */ }
}

public sealed class ShopModuleInstaller : IInstaller
{
    public void Install(IContainerBuilder builder)
    {
        // 构造注入用：依赖方在 Dependencies 里声明 "Shop" 即可注入 IShopService
        builder.Register<IShopService>(_ => new ShopService(), Lifetime.Singleton);
    }
}

要点：① 名字即依赖声明的键，别重名；② 只在 Dependencies 里声明真正要注入的服务来源模块；③ 需要每帧逻辑就实现 ITickableModule；④ 热更程序集加载后用 InstallDeferredModulesAsync(assembly) 二次装配（HybridCLR 预留）。

8 已知边界（v0.1）

  • 作用域链是线性链：先装模块的服务对后装模块全部可见（声明依赖是"保证可见"的子集）；卸载单个中间模块会破坏链——v0.1 只支持整体 ShutdownAsync 逆序卸载。
  • 依赖环不会得到友好报错：ModuleDependencyResolver 的环检测因检查顺序问题形同虚设（见 §2.5 的源码级发现），真实环会栈溢出；建议先查 visiting 再查 visited。
  • HostPlayMode 的静态版本 / 清单 / 断点续传下载流未实现（InitializeAsync 仅初始化包）。
  • HybridCLR 未启用，但 InstallDeferredModulesAsync(params Assembly[]) 入口已预留。
  • VContainer SourceGenerator 未启用（反射注入模式）。
