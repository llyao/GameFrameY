CH.02 · 组件底座

GameFrameX 组件族 — 宿主自举与基础组件

GameFrameX（com.gameframex.unity.*，MIT/Apache-2.0 双许可）是本框架的组件底座：零配置自举的组件宿主 [GameFrameX] 在 AfterSceneLoad 自动创建，13 个组件按 Order 挂载，无需在场景里摆任何东西。本章讲底座包 + Event / FSM / Procedure / Setting / Mono 五个基础组件。

0 快速上手

配方 1：自定义一个事件（含参数）

// ① 定义事件参数：继承 GameEventArgs，Id 约定用类型 FullName（参考包内 OnApplicationFocusChangedEventArgs）
public sealed class PlayerLevelUpEventArgs : GameEventArgs
{
    public static readonly string EventId = typeof(PlayerLevelUpEventArgs).FullName;
    public override string Id => EventId;

    public int NewLevel { get; private set; }
    public static PlayerLevelUpEventArgs Create(int newLevel)
    {
        var e = ReferencePool.Acquire<PlayerLevelUpEventArgs>();   // 走引用池，避免每次分配
        e.NewLevel = newLevel;
        return e;
    }
    public override void Clear() => NewLevel = 0;                  // 回收前清状态（引用池约定）
}

// ② 订阅（幂等）/ ③ 发布（线程安全，下一帧分发）
var ev = GameEntry.GetComponent<EventComponent>();
ev.CheckSubscribe(PlayerLevelUpEventArgs.EventId, (sender, e) =>
{
    var args = (PlayerLevelUpEventArgs)e;
    Debug.Log($"升到 {args.NewLevel} 级");
});
ev.Fire(this, PlayerLevelUpEventArgs.Create(10));
无参数信号直接用字符串 ID：ev.CheckSubscribe("MyGame.Ready", h) / ev.Fire(this, "MyGame.Ready")

1 宿主自举：[GameFrameX] 是怎么来的

理解所有 GameFrameX 包的前提：每个包提供一个 GameFrameworkComponent 子类，全部挂在自动创建的常驻宿主 [GameFrameX] GameObject 上。自举分三个阶段（GameFrameXRuntimeBootstrap.cs）：

  1. [RuntimeInitializeOnLoadMethod(SubsystemRegistration)] → Reset()：重置宿主/贡献者/Options 静态状态（兼容关闭 Domain Reload 的重复 Play）；
  2. [RuntimeInitializeOnLoadMethod(BeforeSceneLoad)] → ClaimAutoInjection() 宣告自动注入接管（此后场景里手工摆放的 GFX 组件会在 Awake 中自我抑制并告警），并应用 Options 贡献者；
  3. [RuntimeInitializeOnLoadMethod(AfterSceneLoad)] → EnsureStarted()：扫描全部 [GameFrameXAutoComponent(order)] 类型 → 创建 [GameFrameX] GameObject（先 SetActive(false)、Play 模式下 DontDestroyOnLoad，按 Order 升序 AddComponent 后再激活）+ GameFrameworkEntry.InstantiateAllModules() 兜底创建模块实例。

各组件挂载顺序由 GameFrameXAutoComponentAttribute.Order 决定（越小越早，Awake 顺序即生效顺序）：

Order组件所属包一句话职责
-10000BaseComponent底座帧率/游戏速度/后台运行；初始化 5 个 Helper；每帧驱动 GameFrameworkEntry.Update（全框架心跳源）
-9000ReferencePoolComponent底座引用池（EventArgs/FSM 均走此池）

2 底座包的关键设施

2.1 GameEntry — 组件注册表

public static class GameEntry
{
    public static T GetComponent<T>() where T : GameFrameworkComponent;  // 自研桥接服务的取组件方式
    public static GameFrameworkComponent GetComponent(Type type);
    public static GameFrameworkComponent GetComponent(string typeName);   // 匹配 FullName 或 Name
    public static void Shutdown(ShutdownType shutdownType);              // None=仅清组件 / Restart=重载场景 / Quit
}
Runtime/Base/GameEntry.cs — 每个组件在 Awake 中注册进 GameEntry 并登记 Manager 模块

2.2 GameFrameworkEntry — 模块容器与心跳

BaseComponent.Update 是全框架唯一每帧入口：BaseComponent.Update → GameFrameworkEntry.Update → 各 IUpdatableModule（Event 队列分发、FSM OnUpdate、Mono Update 监听器…）。模块按 IPrioritizedModule.Priority 注册序轮询；框架关闭时逆序 Shutdown，Application.lowMemory 会通知 ILowMemoryAwareModule。

2.3 BaseComponent — Inspector 可配项

序列化字段默认值说明
m_JsonHelperTypeNameGameFrameX.Runtime.LitJsonHelper框架默认 JSON 实现走 LitJson（反射 Activator 创建后注入 Utility.Json）
m_TextHelper / m_VersionHelper / m_LogHelper / m_CompressionHelperDefault*Helper文本/版本/日志/压缩 Helper，可换实现
m_FrameRate / m_GameSpeed30 / 1对应 Application.targetFrameRate 与 Time.timeScale
m_RunInBackground / m_NeverSleeptrue / true后台运行 / 屏幕不休眠

另有运行时属性：FrameRate / GameSpeed / IsGamePaused / PauseGame() / ResumeGame() 等。

2.4 GameFrameXOptions — 启动配置的唯一入口

GameFrameXOptions.Configure(new AssetOptions { GamePlayMode = EPlayMode.EditorSimulateMode });
GameFrameXOptions.Configure(new ProcedureOptions { UseStartupRunner = true });
GameFrameXOptions.TryGet<AssetOptions>(out var opts);   // 组件 Awake 消费；命中与否都标记"已消费"
GameFrameXOptions.Reset();                               // 框架 Reset 时清空
时序约束

Configure 必须发生在 BeforeSceneLoad（组件首次 TryGet 消费前）；模块已消费后再 Configure 会抛 GameFrameworkException。标了 [GameFrameXStartupOnly] 的字段运行期写入会被拒绝并告警。这就是自研层 GameFrameYStartup.Bootstrap() 抢在建根作用域前先 Configure 的原因。

3 Event 包 — 字符串 ID 事件总线

基于底座 EventPool<T>（ConcurrentQueue + 多播字典），线程安全 Fire、下一帧主线程分发。事件模式为 AllowNoHandler | AllowMultiHandler：无订阅者不报错、同 ID 可挂多个 handler。

API（EventComponent）说明
CheckSubscribe(id, handler)幂等订阅：不存在才 Subscribe（组件层没有裸 Subscribe，裸订阅同 handler 会因多播被回调多次）
CheckUnsubscribe(id, handler)存在才退订
Unsubscribe(id, handler)直接退订
Fire(object sender, string eventId)空参数事件（内部 EmptyEventArgs.Create(eventId)，走引用池）
Fire(object sender, GameEventArgs e)线程安全：入队，下一帧 Update 分发
FireNow(object sender, GameEventArgs e)立即同步分发（非线程安全）
Check(id, handler) / Count(id)查询
SetDefaultHandler(handler)无订阅者时的兜底 handler

字符串 ID 即路由键，约定用 typeof(XxxEventArgs).FullName（如 OnApplicationFocusChangedEventArgs.EventId）；本仓库自研层只用了一个常量："GameFrameY.GameReady"。自定义事件类继承 GameEventArgs 并实现 Id 与 Clear()（引用池回收时清状态）。

SIMULATOR事件总线：Fire 入队 → 下一帧分发

（无订阅）

4 FSM 包 — 泛型有限状态机

每个 Owner 类型可建多台（可命名）状态机；状态带完整生命周期与 string → Variable 黑板。Procedure 包就建在它上面。

// 创建一台状态机（FsmComponent 门面）
IFsm<Player> fsm = GameEntry.GetComponent<FsmComponent>().CreateFsm(player,
    new IdleState(), new MoveState(), new AttackState());
fsm.Start<IdleState>();                    // 只能 Start 一次；重跑需 Reset()

// 状态基类
public class MoveState : FsmState<Player>
{
    protected override void OnInit(IFsm<Player> fsm) { }
    protected override void OnEnter(IFsm<Player> fsm) { }
    protected override void OnUpdate(IFsm<Player> fsm, float elapse, float realElapse) { }
    protected override void OnLeave(IFsm<Player> fsm, bool isShutdown) { }
    protected void ChangeState<TState>(IFsm<Player> fsm);   // 内部：OnLeave → 切换 → OnEnter（同步完成）
}

// 黑板（值经 Variable 包装：VarInt32 / VarString / …）
fsm.SetData("HP", VarInt32.Create(100));
int hp = fsm.GetData<VarInt32>("HP").Value;
要点：OnUpdate 由 GameFrameworkEntry.Update 驱动、OnFixedUpdate 由 FsmComponent.FixedUpdate 驱动；FSM 对象本身走引用池

其他能力：HasState/GetState/GetAllStates、运行期 AddState/RemoveState、fsm.Reset()（退出当前态、清黑板、可重新 Start）、CurrentStateTime（当前态停留时长）。ChangeState 校验目标状态存在，不存在抛异常。

5 Procedure 包 — 流程管理（FSM 的应用）

ProcedureManager 内部创建一台 IFsm<IProcedureManager>，流程类即状态（ProcedureBase : FsmState<IProcedureManager>）。本项目没有走组件默认的"反射建流程"路径：

// GameFrameYStartup 注入：流程由我们的启动协调器自管
GameFrameXOptions.Configure(new ProcedureOptions { UseStartupRunner = true });

// GameFrameYGameLauncher 里（代码建流程，不依赖 Inspector 类型名列表）
var procedures = new ProcedureBase[] { launch, patch, loadConfig, enterGame };
procedureComponent.ReinitializeProcedures(procedures, launch);   // Destroy + 重建 FSM
procedureComponent.Procedure.StartProcedure(launch.GetType());
UseStartupRunner = true 的含义

ProcedureComponent.Start() 协程直接 yield break——组件只负责 Awake 注册 IProcedureManager，Initialize + StartProcedure 由外部（本项目即 GameFrameYGameLauncher）接管，避免重复 Initialize 报 "Already exist FSM"。为 false（默认）时走旧路径：按 Inspector 的 m_AvailableProcedureTypeNames 反射建流程并自动启动。

常用 API：CurrentProcedure / CurrentProcedureTime / HasProcedure<T>() / GetProcedure<T>() / DestroyProcedures()。流程内跳转用 ChangeState<TState>(fsm)（自研层封装为 GoTo<T>()）。

6 Setting 包 — 键值持久化设置

var setting = GameEntry.GetComponent<SettingComponent>();
setting.SetInt("Audio.Volume", 80);
setting.SetBool("FirstLaunch", false);
setting.SetObject("Player.Preferences", new Preferences());   // 对象经 Utility.Json(LitJson) 序列化为 string
setting.Save();                                               // 显式落盘（SetXxx 只写内存！框架关闭时也会自动 Save）
int v = setting.GetInt("Audio.Volume", defaultValue: 100);    // 每种类型都有带默认值重载
项说明
支持类型bool / int / float / string / 任意 class + new()（对象走 JSON）
默认后端PlayerPrefsSettingHelper → ISettingStorageBackend → Unity PlayerPrefs（bool 存为 int 0/1；Editor 恒用 PlayerPrefs）
备选后端DefaultSettingHelper：全量内存字典 → 文件 persistentDataPath/GameFrameworkSetting.dat（GameFrameworkSerializer 加密流）
渠道扩展真机可注册小游戏渠道后端（SettingStorageBackendFactory 保留首个注册，未注册回落 PlayerPrefs）
消费方Localization 用它持久化语言（键 LocalizationComponent.Language，见 06 章）

7 Mono 包 — MonoBehaviour 生命周期桥

让纯 C# 模块/服务（无 GameObject）也能挂每帧逻辑，并把应用前后台切换转成事件总线的两个标准事件：

var mono = GameEntry.GetComponent<MonoComponent>();
mono.AddUpdateListener((dt, unscaledDt) => { /* 每帧 */ });
mono.AddFixedUpdateListener((fdt, _) => { /* 物理帧 */ });
mono.AddLateUpdateListener((dt, _) => { /* 后期帧 */ });
mono.AddOnApplicationPauseListener(paused => { /* true=进后台 */ });
mono.AddOnApplicationFocusListener(focused => { });
// 移除：RemoveXxxListener；null 回调会被拒绝并 Log.Fatal

Focus/Pause 同时会 Fire OnApplicationFocusChangedEventArgs / OnApplicationPauseChangedEventArgs（ID = 类型 FullName，带 IsFocus/IsPause 字段），可在事件总线上订阅。内部是 6 条 LinkedList + lock + 快照调用。
