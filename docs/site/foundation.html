配方 1：UniTask 实战四式

// ① 物体销毁即取消（UI/场景对象里的标准写法）
private void Start() { RefreshLoop().Forget(); }

async UniTaskVoid RefreshLoop()
{
    var ct = this.GetCancellationTokenOnDestroy();   // destroyCancellationToken 的安全包装
    while (!ct.IsCancellationRequested)
    {
        await UniTask.Delay(1000, cancellationToken: ct);
        Refresh();
    }
}   // Forget() 消费异常（进 UniTaskScheduler.UnobservedTaskException）

// ② 并行 + 超时
var (a, b) = await UniTask.WhenAll(LoadA(), LoadB());
var result = await FetchAsync().Timeout(TimeSpan.FromSeconds(5));

// ③ 等条件成立（自研层等组件就绪同款）
await UniTask.WaitUntil(() => _ready);

// ④ 取消但不抛异常
var (isCanceled, value) = await LoadAsync().SuppressCancellationThrow();
if (isCanceled) return;

1 UniTask：为什么全框架都用它

1.1 与 Task / 协程的本质区别

System.Threading.Tasks.TaskIEnumerator 协程UniTask
类型class，每次 await 有分配interface + 装箱迭代器readonly struct（source+token 两个字段），source 走 TaskPool 池化，热路径零分配
驱动线程池 + SynchronizationContext.Post 回主线程MonoBehaviour（物体禁用/销毁即停）PlayerLoop 原生时机恢复（16 档 PlayerLoopTiming），不需要 SyncContext
await 次数多次Start 一次一次性（await 后失效）；要多次 await 先 .Preserve()
异常UnobservedTaskException 兜底直接抛到 Unity无兜底：显式 Forget() 消费并进 UniTaskScheduler.UnobservedTaskException
取消/返回值支持都难原生 CancellationToken 链 + 泛型返回 UniTask<T>

两个高频坑
  • async void 别用——异常会直接打崩；事件回调里用 async UniTaskVoid F() + Forget()。本仓库 GameFrameYProcedure.RunFlow 就是标准示范（UniTask.Void + try/catch）。
  • 同一段逻辑里 await UniTask.Delay(...) 与 UniTask.Yield() 的恢复时机由 PlayerLoopTiming 决定（默认 Update），与 MonoBehaviour 的 Update 相对顺序是确定的——见下面的时机图。

2 VContainer：DI 脊柱

2.1 核心概念与注册 API

// 作用域（MonoBehaviour；本项目全部代码创建，不用场景 prefab）
LifetimeScope.Create(new GameFrameYRootInstaller(), "GameFrameY Root");   // 静态工厂建根
scope.CreateChild(installer, "GameFrameY.Module.Asset");                  // 子作用域（Build 时注册 LifetimeScope 自身）

// 注册（IContainerBuilder）
builder.Register<IServiceRegistry>(r => new ServiceRegistry(r), Lifetime.Singleton);
builder.Register<IAssetService>(_ => new AssetService(), Lifetime.Singleton);   // 接口→实现
builder.RegisterInstance(new GameFrameYLaunchSettings());                        // 已有实例
builder.RegisterInstance(new GameFrameYStartupStatus());                         // 启动状态
builder.RegisterEntryPoint<GameModuleManager>(Lifetime.Singleton).AsSelf();       // EntryPoint + 具体类型解析
// 流式：.As<T>() / AsImplementedInterfaces() / Keyed(obj) / WithParameter(name, value)

// 解析（IObjectResolver）
resolver.Resolve<T>();            // 找不到抛 VContainerException
resolver.TryResolve<T>(out var t); // 沿 Parent 链向上找，失败返回 false
resolver.ResolveOrDefault<T>(default);
resolver.Inject(instance);         // 对已存在对象补属性/方法注入

Lifetime 语义（源码级，见 09 章 §2）：Transient（每次新建）；Singleton——唯一性范围是"注册它的作用域"（注册在本作用域 → 缓存于本作用域、随作用域 Dispose 销毁；注册不在 → 上抛 Parent 解析；只有根容器注册的才是全局共享）；Scoped（本作用域缓存 + disposables 链）。注入方式：构造函数（最多一个 [Inject] 构造）+ [Inject] 属性/字段/方法；构建期做循环依赖检查。诊断窗口：VContainer Diagnostics（EnableDiagnostics）。模块的子作用域服务需显式导出到中央服务注册表，根 resolver 不会向下查找子作用域。

2.2 EntryPoint：容器驱动的生命周期

RegisterEntryPoint 会注册 EntryPointDispatcher 并挂 Build 回调——容器 Build 完成的那一刻同步 Dispatch：

接口方法执行时机
IInitializable / IPostInitializableInitialize() / PostInitialize()Build 回调内同步执行（先于一切帧）
IStartable / IPostStartableStart() / PostStart()PlayerLoopTiming.Startup（EarlyUpdate，一次性；早于 MonoBehaviour.Start）
IAsyncStartableUniTask StartAsync(CancellationToken)Startup 时机 fire-and-forget；异常经 EntryPointExceptionHandler 发布
ITickable / IPostTickableTick() / PostTick()Update / PostUpdate（每帧）
IFixedTickable / IPostFixedTickableFixedTick()FixedUpdate / PostFixedUpdate
ILateTickable / IPostLateTickableLateTick()PreLateUpdate / PostLateUpdate

本项目：GameModuleManager 实现三个 Tickable（模块 Tick 泵）；GameFrameYGameLauncher 实现 IAsyncStartable（启动编排）。

VContainer 向 Unity 原生 PlayerLoop 的 Initialization / EarlyUpdate / FixedUpdate / Update / PreLateUpdate 五个区段各插入一对子系统（一次性项 MoveNext 返回 false 后自动出队）。场景 LifetimeScope 的父子解析优先级：Inspector 引用 → 子类 FindParent 覆写 → 场景按类型查找 → EnqueueParent 全局覆盖 → VContainerSettings 根作用域。本项目没用 VContainerSettings——根作用域全部代码创建。

5 Localization（本地化字典）

var loc = GameEntry.GetComponent<LocalizationComponent>();
loc.Language = LocalizationCode.ChineseSimplified;   // "zh_CN"；写入 Setting 持久化 + 广播三段事件
string s = loc.GetString("UI.OK");                  // 无参
string s2 = loc.GetString("UI.Welcome", player.Name, level);  // 17 个强类型重载（最多 16 参，无装箱）
bool has = loc.HasRawString("UI.OK");
bool added = loc.AddRawString("UI.OK", "确定");     // 字典注入入口（本版本不经组件加载字典文件）

机制要点：语言码用 .NET CultureInfo 风格（zh_CN / en_US，DefaultLocalizationHelper 把 - 换 _）；切换语言时依次 Fire Before / On / After 三个事件（带 old/new）；UIForm 基类订阅语言切换事件自动调 UpdateLocalization() 刷新界面文本。启动配置 LocalizationOptions：DefaultLanguage/EditorLanguage = "zh_CN"、IsEnableEditorMode = false。
