CH.07 · 配置

Luban — 一份定义，双端生成

配置体系的原则：定义与数据只有一份（Config/Defines/schema.xml + Config/Datas/*.json），Luban v5.1.0 按分组生成两端产物——客户端 cfg 命名空间代码 + bytes（走 YooAsset 进包），服务端 GameFrameY.Config + bytes（直接编译）。生成器全量源码也在仓里，改生成逻辑后 build-luban 重出工具。

Luban v5.1.0（生成器源码 vendored） 运行时：com.gameframey.luban（ByteBuf） 4 张表 · 2 枚举 · group c/s 过滤

2 luban.conf（全文 + 注解）

{
  "groups": [
    { "names": ["c"], "default": true },      // c=客户端组；default:true ⇒ 未标 group 的表属于该组
    { "names": ["s"], "default": true }       // s=服务端组；两个组都 default ⇒ 未标注 = 双端都导出
  ],
  "schemaFiles": [
    { "fileName": "Defines", "type": "" }     // schema 目录；type:"" 用内置 xml 格式（module/bean/table 标签）
  ],
  "dataDir": "Datas",                          // 数据根目录；input="*@item.json" 的 * 代表此目录
  "targets": [
    { "name": "client", "manager": "Tables", "groups": ["c"], "topModule": "cfg" },
    { "name": "server", "manager": "Tables", "groups": ["s"], "topModule": "GameFrameY.Config" }
  ]
}
Config/luban.conf — target 决定：分组过滤（表 ∩ 组）+ 生成代码顶层命名空间 + manager 类名

3 schema.xml（全文 + 注解）

<module name="">
    <enum name="ItemQuality">   <!-- White=0 Green=1 Blue=2 Purple=3 Orange=4 --> </enum>
    <enum name="ServerState">   <!-- Normal=0 Busy=1 Maintain=2 -->              </enum>

    <bean name="Item" comment="道具配置">                    <!-- 普通字段 bean -->
        <var name="id"      type="int"         comment="道具ID"/>   <!-- 首字段自动成为 map 表 key -->
        <var name="name"    type="string"/>
        <var name="desc"    type="string"/>
        <var name="price"   type="int"/>
        <var name="quality" type="ItemQuality"/>              <!-- 枚举字段：生成代码里是强类型 enum -->
        <var name="stackable" type="bool"/>
    </bean>
    <bean name="GlobalConfig" comment="全局配置（单例表）"/>
    <bean name="ServerInfo"   comment="服务器列表"/>
    <bean name="RobotName"    comment="机器人名字（仅服务端使用，演示 group 过滤）"/>

    <!-- group: c=客户端 s=服务端；未标注默认双端。input 的 * 从 dataDir 取文件 -->
    <table name="TbItem"       value="Item"        input="*@item.json"      comment="道具表"/>
    <table name="TbGlobal"     value="GlobalConfig" mode="one" input="global.json" comment="全局配置"/> <!-- mode=one 单例表 -->
    <table name="TbServerList" value="ServerInfo"  input="*@serverlist.json"/>
    <table name="TbRobotName"  value="RobotName"   input="*@robotname.json" group="s" comment="机器人名（仅服务端）"/>
</module>
要点说明
表名 ↔ 数据文件由 input 属性显式映射（数据文件名不带 Tb 前缀：TbItem ← item.json）
map 模式（默认）生成 Dictionary<key,value> + List，key = bean 首字段；GetOrDefault/Get/this[]/DataMap/DataList
mode="one" 单例整表一行（数据文件直接是 JSON 对象非数组）；生成 Data 属性 + 逐字段转发属性
group 过滤作用于表与数据；bean 类不做组过滤——客户端 Generate 目录会残留无引用的 RobotName.cs（无害死代码）

6 生成脚本（全文 + 参数注解）

#!/usr/bin/env bash
set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
LUBAN_DLL="$SCRIPT_DIR/Tools/Luban/Luban.dll"

dotnet "$LUBAN_DLL" \
    -t client -c cs-bin -d bin \            # target=client；C#+bin 风格代码；二进制数据
    --conf "$SCRIPT_DIR/luban.conf" \
    -x "outputCodeDir=../Client/Assets/GameFrameY/Config/Generate" \   # 代码 → cfg（进 Unity）
    -x "outputDataDir=../Client/Assets/Bundles/Config" \               # bytes → YooAsset 收集目录
    "$@"                                    # 透传额外参数
echo "[gen-client] OK"
#!/usr/bin/env bash
set -euo pipefail
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
LUBAN_DLL="$SCRIPT_DIR/Tools/Luban/Luban.dll"

dotnet "$LUBAN_DLL" \
    -t server -c cs-bin -d bin \            # target=server（groups:["s"]）
    --conf "$SCRIPT_DIR/luban.conf" \
    -x "outputCodeDir=../Server/Config/Generate" \    # 代码 → GameFrameY.Config 命名空间
    -x "outputDataDir=../Server/Config/Datas" \       # bytes → csproj CopyToOutputDirectory
    "$@"
echo "[gen-server] OK"

.bat 版本参数一致（多 errorlevel 检查）。参数含义：-t 选 luban.conf 的 target；-c cs-bin = C# 代码 + ByteBuf 二进制序列化风格；-d bin = 数据导出为 .bytes；-x outputCodeDir/outputDataDir = 两个输出目录（本仓只用这两个 -x 变量）。

7 运行时链路：bytes → cfg.Tables

// ① 生成的 Tables（节选）：loader 委托按表逻辑名取缓冲
public Tables(System.Func<string, ByteBuf> loader)
{
    TbItem = new TbItem(loader("tbitem"));          // ← 名字 = 属性名小写 = bytes 文件名 = YooAsset 地址
    TbGlobal = new TbGlobal(loader("tbglobal"));
    TbServerList = new TbServerList(loader("tbserverlist"));
    ResolveRef();                                    // 二段式：先建表后解引用（ref/path 校验）
}

// ② 生成的 bean：逐字段 ReadXxx，全部 readonly（不可变配置对象）
public Item(ByteBuf _buf)
{
    Id = _buf.ReadInt();                  // int
    Name = _buf.ReadString();             // string（ReadSize 前缀 + UTF8 字节）
    Desc = _buf.ReadString();
    Price = _buf.ReadInt();
    Quality = (ItemQuality)_buf.ReadInt();// enum → ReadInt 强转
    Stackable = _buf.ReadBool();          // bool
}
public const int __ID__ = 2289459;        // Luban 编译期类型哈希（多态 bean 用）
public override int GetTypeId() => __ID__;

// ③ 消费（DemoModule）
var item = config.Tables.TbItem.GetOrDefault(10001);   // map 表
var url  = config.Tables.TbGlobal.PatchUrl;            // one 表字段转发
运行时包 com.gameframey.luban 提供 ByteBuf/BeanBase/ITypeId/SimpleJSON；ByteBuf 还有 varint 变长整数、segment 段（多态 bean 前置长度）、TryDeserializeInplaceByteBuf（网络半包）等能力，网络包未来可复用

8 改表工作流与工具链

加一张表 / 改一个字段（标准流程）
  1. Defines/schema.xml：声明 bean 与 table（决定 group 与 input 文件名）；
  2. Datas/xxx.json：写数据；
  3. cd Config && ./gen-client.sh && ./gen-server.sh；
  4. 回 Unity：新表 bytes 出现在 Bundles/Config，ConfigService 反射自动纳入加载（无需改加载代码）；YooAsset Collector 若报 GUID 不匹配，窗口里 Fix（见 03 章）；
  5. 服务端：Server/Config 重新生成后 dotnet build 即可。

Tools/ 目录：

  • LubanSource/：Luban v5.1.0 全量源码（net8.0），插件化管线：Luban.Core（类型系统）/ Schema.Builtin（xml）/ DataLoader.Builtin（json/excel/yaml/lua…）/ DataTarget.Builtin（bin/json/bson/lua…）/ 各语言代码插件（C#/TS/Lua/Go/Rust…）/ Protobuf、FlatBuffers、MsgPack 消息方案插件 / Luban.Agent（AI）与 Luban.Mcp。
  • Luban/：构建产物（Luban.dll + 全部依赖 + Templates），gen 脚本直接引用——日常生成不需要构建。
  • build-luban.bat|sh：改了 LubanSource 后重出工具：dotnet build LubanSource/src/Luban/Luban.csproj -c Release -o Luban。
  • vendor_packages.py：Unity 包源码化脚本（与 Luban 无关，服务于 Client/Packages）：按 DIRECT 表浅克隆 → 递归补依赖 → Tests/ 改名 Tests~/（避免 Unity 导入测试程序集）。
  • _examples/：Luban 官方示例快照（DataTables/MiniTemplate 等，仅参考）。
为什么不用 com.gameframex.unity.focus-creative-games.luban？

该包命名空间是 LuBan.Runtime，与 Luban v5 生成代码不兼容；故直接 vendor 了上游 src/Luban.Tests/RuntimeSupport 为 com.gameframey.luban（命名空间 Luban），与双端生成代码配套（package.json 注明）。
