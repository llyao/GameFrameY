Network — 通道制网络与双端协议

network 包（3.0.0）是命名通道（Channel）制：每条通道一份 INetworkChannelHelper 编解码管线，TCP Socket 与 WebSocket 双后端（编译宏选择），带可插拔分包、心跳、特性驱动消息分发与异步 RPC。底层 WebSocket 由 psygames.unitywebsocket（2.9.3）提供；协议约定在 Protobuf/ 目录与 GameFrameX.Tools 生成体系。

// 注入 INetworkService（Network 模块装配后即可构造注入/服务定位）
public sealed class NetDemoModule : GameModuleBase

    {

}

配方 2：接收服务器推送（正确写法：方法级特性）

注意：MessageHandler 是「方法级」特性，不是类基类

处理器类实现 IMessageHandler（唯一成员 Register()），在方法上标 [MessageHandler(typeof(NoticeNotify), nameof(OnNotice))]。可被特性分发的消息必须是 MessageObject 且实现 INotifyMessage（推送）；请求/响应对（Req/Resp）由 RPC 状态机匹配，不走特性。注册入口是公开静态方法 ProtoMessageHandler.Add(handler)（何时调用由你决定，比如模块 OnStartAsync；移除用 Remove）。

public sealed class DemoNetHandler : IMessageHandler
{
    public void Register()
    {
        ProtoMessageHandler.Add(this);   // 反射扫描本类所有 [MessageHandler] 方法并登记
    }

    [MessageHandler(typeof(NoticeNotify), nameof(OnNotice))]  // 消息类型 + 方法名（nameof 防拼错）
    private void OnNotice(NoticeNotify message)               // 恰好 1 个参数，参数类型必须等于消息类型
    {
        // 通道在主线程 Update 中消费队列后反射调用到这里（内部缓存 object[] 避免每次分配）
        GfyLog.Info($"[Net] 收到公告：{message.Content}");
    }
}
ProtoMessageHandler 维护 ConcurrentDictionary<Type, List<MessageHandlerAttribute>>；重复注册同一方法会 Log.Error

1 通道制架构

NetworkComponent（[GameFrameXAutoComponent(1000)]，门面：创建/查找/销毁通道）
   │  CreateNetworkChannel(name, helper)
   ▼
NetworkChannelBase（每通道一个：发送队列 / 接收队列 / 心跳 / RPC 状态）
   │  后端选择（NetworkManager.cs 编译期决定）：
   │    #if (ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL) || FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET
   │        WebSocketNetworkChannel ──► UnityWebSocket（WebGL: JSLIB / 其他: System.Net.WebSockets）
   │    #else
   │        SystemTcpNetworkChannel ──► 原生 System.Net.Sockets.Socket
   │    #endif
   ▼
INetworkSocket（统一适配层：Send / Shutdown / 二进制接收回调 / 关闭原因+错误码）

主线程每帧（NetworkComponent.Update 驱动）：
ProcessSend → ProcessReceive → ProcessHeartBeat → ProcessReceivedMessage → PRpcState.Update

组件还会把通道事件转发到事件总线：NetworkConnectedEventArgs / NetworkClosedEventArgs{Channel, Reason, ErrorCode} / NetworkMissHeartBeatEventArgs / NetworkErrorEventArgs（没有独立的 "Disconnected" 事件，断开即 Closed）。

3 INetworkChannelHelper — 编解码的唯一扩展点

public interface INetworkChannelHelper
{
    void Initialize(INetworkChannel networkChannel);   // DefaultNetworkChannelHelper：反射扫描全部 IPacketHandler 自动注册
    void Shutdown();
    void PrepareForConnecting();
    bool SendHeartBeat();                              // 心跳包由 helper 决定（IHeartBeatMessage）
    bool SerializePacketHeader<T>(T msg, MemoryStream dest, out byte[] body);  //包头
    bool SerializePacketBody(byte[] body, MemoryStream dest);                   // 包体
    bool DeserializePacketHeader(byte[] source);
    bool DeserializePacketBody(byte[] source, int messageId, out MessageObject msg);
}
// 默认实现 DefaultNetworkChannelHelper 还提供 SetChannelSerializer(IMessageSerializer)，
// 须在 Initialize 之前调用（protobuf-net / 自定义序列化器在此接入）

配套默认管线类：DefaultPacketSendHeaderHandler / DefaultPacketSendBodyHandler / DefaultPacketReceiveHeaderHandler / DefaultPacketReceiveBodyHandler / BasePacketHeartBeatHandler / DefaultMessageSerializer。消息基类体系在 Runtime/Network/Base/：MessageObject、IRequestMessage / IResponseMessage / INotifyMessage / IHeartBeatMessage。接收分发不走接口回调——由 ProtoMessageHandler.GetHandlers(msgType) 按 [MessageHandler] / [MessageTypeHandler] 特性反射注册的处理器在主线程 Update 消费队列时逐个 Invoke。

4 心跳机制（源码级）

private void ProcessHeartBeat(float realElapseSeconds)
{
    if (PHeartBeatInterval > 0f)
    {
        lock (PHeartBeatState)
        {
            PHeartBeatState.HeartBeatElapseSeconds += realElapseSeconds;
            if (PHeartBeatState.HeartBeatElapseSeconds >= PHeartBeatInterval)
            {
                sendHeartBeat = true;                       // 到点：发心跳
                PHeartBeatState.HeartBeatElapseSeconds = 0;
                PHeartBeatState.MissHeartBeatCount++;       // 同时丢跳计数 +1
            }
            if (sendHeartBeat && PFocusHeartbeat)
                if (PNetworkChannelHelper.SendHeartBeat()) return;   // 发出即认为本回合健康
            if (PHeartBeatState.MissHeartBeatCount > MissHeartBeatCountByClose)
                shouldClose = true;
        }
        if (shouldClose)
            Close(NetworkCloseReason.MissHeartBeat, (ushort)NetworkErrorCode.MissHeartBeatError);
    }
}
要点：收到任意数据包会重置计时（ResetHeartBeatElapseSecondsWhenReceivePacket）；MissHeartBeatCount 超阈值自动断开并广播 NetworkMissHeartBeatEventArgs；没有自动重连——重连由上层订阅 NetworkClosedEventArgs 自行处理

5 异步 RPC：Call<TResult>

Send 是即发即弃；Call<TResult>(req) 走 PRpcState：请求带序列号，收到匹配的 IResponseMessage 时 TryReply 完成 Task；超时（NetworkOptions.RpcTimeout，默认 5000ms）走 SetRPCErrorHandler 回调。RPC 的开始/结束/错误码三类 handler 都可挂。推送消息的分发写法见 快速上手 · 配方 2（方法级 [MessageHandler] 特性，主线程执行）。

更深一层的源码事实（为排障与定制编解码时用）：

9.1 线程模型：两级队列，主线程收敛

// 发送侧：Send<T> 只入链表（任意线程可调），真正序列化在主线程 Update 里
public void Send<T>(T messageObject) where T : MessageObject
{
    lock (PSendPacketPool) { PSendPacketPool.AddLast(messageObject); }   // ① 发送队列（链表+锁）
}
protected virtual bool ProcessSend()          // ② 主线程每帧（NetworkComponent.Update 驱动）
{
    lock (PSendPacketPool)
    {
        while (PSendPacketPool.First != null) { /* 逐条 ProcessSendMessage 序列化进同一个 MemoryStream */ }
        PSendState.Stream.Position = 0L;      // ③ 一批消息合入一个缓冲，一次性下发 socket
        return true;
    }
}

// 接收侧：socket 回调线程收字节 → 反序列化 → 跨线程队列 → 主线程消费
protected readonly ConcurrentQueue<MessageObject> m_ExecutionMessageQueue = new();
// 主线程 Update：while (m_ExecutionMessageQueue.TryDequeue(out var msg)) → 先 PRpcState.TryReply，
// 未命中再走 [MessageHandler] 分发（NetworkChannelBase.ProcessReceivedMessage）
即：业务代码可以放心在任意线程 Send；所有回调（RPC 完成/handler）都保证主线程执行。基类的 ProcessReceive() 是空的——字节接收在各 Socket 实现（SystemNetSocket / WebSocketNetSocket）的回调里

9.2 分包字节格式（DefaultPacketSendHeaderHandler）

一帧 = 包头(14B) + 包体
包头：uint PacketLength(4B) + byte OperationType(1B) + byte ZipFlag(1B)
      + int UniqueId(4B, RPC 匹配键) + int CmdId(4B, 消息 ID = (moduleId<<16)+seqId)
包体：IMessageSerializer 序列化字节（≥ LimitCompressLength=512 时可经 IMessageCompressHandler 压缩，ZipFlag 置位）
接包：DefaultPacketReceiveHeaderHandler 按同格式读头 → DefaultPacketReceiveBodyHandler 反序列化出 MessageObject

序列化器是可插拔注册的：通道级 SetChannelSerializer 或 MessageSerializerRegistry.RegisterGlobal()；DefaultMessageSerializer 本身只是"未注册即报错"的哨兵（protobuf 等具体实现在接入 GameFrameX.Tools 生成代码后提供）。

9.3 RPC 匹配（RpcState）

// Call<TResult> 登记等待项（键 = 消息 UniqueId）
var data = RpcMessageData.Create(messageObject as IRequestMessage, _rpcTimeout, isIgnoreErrorCode);
_waitingReplyHandlingObjects.TryAdd(messageObject.UniqueId, data);   // ConcurrentDictionary

// 收到响应：TryReply 用 UniqueId 匹配
public bool TryReply(MessageObject message)
{
    if (message.GetType().IsImplWithInterface(typeof(IResponseMessage))
        && _waitingReplyHandlingObjects.TryRemove(message.UniqueId, out var waiting))
    {
        waiting.Reply(message as IResponseMessage);          // 完成 Task
        if (message.ErrorCode != 0 && !waiting.IsIgnoreErrorCode)
            _rpcErrorCodeHandler?.Invoke(this, message);     // 业务错误码回调
        return true;
    }
    return false;   // 未命中 → 走 [MessageHandler] 推送分发
}
// 超时：每帧 IncrementalElapseTime 累计，到期收集移除；注意 RpcState 构造强制 timeout ≥ 3000ms
所以 RPC 的"键"是每条请求的 UniqueId 而不是消息 ID——同一种请求可以并发多次；响应匹配不到等待项时才会落到推送分发

9.4 TCP 接收状态机：半包不是异常

SystemTcpNetworkChannel 不把一次 Socket 回调当成一条完整消息。PReceiveState.Stream 会跨多个 BeginReceive 保留当前包的字节：先补齐 14 字节头，再按 PacketLength - PacketHeaderLength 读取包体；头或体没收完整时继续异步接收，只有完整包才进入反序列化。

private void ReceiveCallback(IAsyncResult asyncResult)
{
    int bytesReceived = PSystemNetSocket.EndReceive(asyncResult);
    PReceiveState.Stream.Position += bytesReceived;

    if (PReceiveState.Stream.Position < PReceiveState.Stream.Length)
    {
        ReceiveAsync();                    // 当前包还没收完：保留 Stream，继续补数据
        return;
    }

    PReceiveState.Stream.Position = 0L;
    bool success = PReceiveState.PacketHeader != null
        ? ProcessPackBody()                 // 头已解析，本轮只处理体
        : ProcessPackHeader();              // 先读 14B，计算下一段体长度

    if (success)
        ReceiveAsync();                     // 一个包完成后，马上准备下一个包
    else
        Close("Packet process error.", (ushort)NetworkErrorCode.DeserializePacketError);
}

private bool ProcessPackBody()
{
    int bodyLength = (int)(PReceiveState.PacketHeader.PacketLength
        - PReceiveState.PacketHeader.PacketHeaderLength);
    var body = new byte[bodyLength];
    _ = PReceiveState.Stream.Read(body, 0, bodyLength);
    if (PReceiveState.PacketHeader.ZipFlag != 0)
        body = MessageDecompressHandler.Handler(body);

    bool success = PNetworkChannelHelper.DeserializePacketBody(
        body, PacketReceiveHeaderHandler.Id, out var messageObject);
    if (success)
    {
        messageObject.SetUpdateUniqueId(PacketReceiveHeaderHandler.UniqueId);
        m_ExecutionMessageQueue.Enqueue(messageObject);
        PReceiveState.PrepareForPacketHeader();
    }
    return success;
}
TCP 的连续字节流可能把一个包拆成多次回调，也可能一次带来多个包；状态机用 Stream.Position、PacketHeader 和 PrepareForPacketHeader 把边界重新拼出来。解析失败会关闭通道，而不是把半包交给业务层。

9.5 连接成功：从 Socket 建连到可用通道

private void ConnectAsync(object userData)
{
    PIsConnecting = true;
    m_ConnectState = new ConnectState(PSystemNetSocket, userData);
    PSystemNetSocket.BeginConnect(
        ConnectEndPoint.Address, ConnectEndPoint.Port,
        ConnectCallback, m_ConnectState);
}

private void ConnectCallback(IAsyncResult asyncResult)
{
    PIsConnecting = false;
    var state = (ConnectState)asyncResult.AsyncState;
    try
    {
        ((SystemNetSocket)state.Socket).EndConnect(asyncResult);
    }
    catch (ObjectDisposedException) { return; }
    catch (Exception e)
    {
        NetworkChannelError?.Invoke(this, NetworkErrorCode.ConnectError,
            SocketError.Success, e.ToString());
        Close(NetworkCloseReason.ConnectClose, (ushort)SocketError.Success);
        return;
    }

    m_SentPacketCount = 0;
    m_ReceivedPacketCount = 0;
    lock (PSendPacketPool) PSendPacketPool.Clear();
    lock (PHeartBeatState) PHeartBeatState.Reset(true);
    PActive = true;
    NetworkChannelConnected?.Invoke(this, state.UserData);
    ReceiveAsync();
}

这里的 Connected 事件不是 BeginConnect 一调用就触发，而是在 EndConnect 成功、收发计数清零、发送队列清空、心跳状态重置之后才触发。连接异常分成两类：已释放的 Socket 直接结束回调；其他异常先发 ConnectError，再关闭通道。

WebSocket 适配器的边界

在 ENABLE_GAME_FRAME_X_WEB_SOCKET 下，WebSocketNetSocket 只把 e.IsBinary 的 RawData 转给接收回调，文本帧会被忽略；OnError 把连接任务置为 false。当前适配器中 30 秒超时与“连接结果为 false 时抛异常”的代码仍是注释，调用方不能把它当成内置超时保障，应在上层补连接超时与失败策略。

9.6 RPC 等待项：超时先完成任务，再清理索引

internal bool IncrementalElapseTime(long time)
{
    ElapseTime += time;
    if (ElapseTime < Timeout)
        return false;

    m_Tcs.TrySetException(new TimeoutException(
        $"Rpc call timeout! Message FullName:{RequestMessage.GetType().FullName}"));
    return true;
}

public void Update(float elapseSeconds, float realElapseSeconds)
{
    long elapsed = (long)(realElapseSeconds * 1000);
    foreach (var item in _waitingReplyHandlingObjects)
    {
        if (!item.Value.IncrementalElapseTime(elapsed))
            continue;

        _timeoutIds.Add(item.Key);
        _rpcErrorHandler?.Invoke(this, item.Value.RequestMessage as MessageObject);
    }

    foreach (var id in _timeoutIds)
        _waitingReplyHandlingObjects.TryRemove(id, out _);
}

public void Dispose() // Reset() 使用同一套清理语义
{
    foreach (var item in _waitingReplyHandlingObjects)
        item.Value.Dispose();                 // TrySetCanceled()
    _waitingReplyHandlingObjects.Clear();
}
RpcState 构造时小于 3000ms 会直接抛 ArgumentOutOfRangeException；正常超时会先让 TaskCompletionSource 进入异常态并调用错误回调，下一步才从 ConcurrentDictionary 移除。断线重连可调用 Reset()，它会把全部未完成 RPC 取消，而不是静默遗留。
