CH.05 · 网络

Network — 通道制网络与双端协议

network 包（3.0.0）是命名通道（Channel）制：每条通道一份 INetworkChannelHelper 编解码管线，TCP Socket 与 WebSocket 双后端（编译宏选择），带可插拔分包、心跳、特性驱动消息分发与异步 RPC。底层 WebSocket 由 psygames.unitywebsocket（2.9.3）提供；协议约定在 Protobuf/ 目录与 GameFrameX.Tools 生成体系。

com.gameframex.unity.network 3.0.0 psygames.unitywebsocket 2.9.3 消息 ID = (moduleId << 16) + seqId

1 通道制架构

NetworkComponent（[GameFrameXAutoComponent(1000)]，门面：创建/查找/销毁通道）
   │  CreateNetworkChannel(name, helper)
   ▼
NetworkChannelBase（每通道一个：发送队列 / 接收队列 / 心跳 / RPC 状态）
   │  后端选择（NetworkManager.cs 编译期决定）：
   │    #if (ENABLE_GAME_FRAME_X_WEB_SOCKET && UNITY_WEBGL) || FORCE_ENABLE_GAME_FRAME_X_WEB_SOCKET
   │        WebSocketNetworkChannel ──► UnityWebSocket（WebGL: JSLIB / 其他: System.Net.WebSockets）
   │    #else
   │        SystemTcpNetworkChannel ──► 原生 System.Net.Sockets.Socket
   │    #endif
   ▼
INetworkSocket（统一适配层：Send / Shutdown / 二进制接收回调 / 关闭原因+错误码）

主线程每帧（NetworkComponent.Update 驱动）：
ProcessSend → ProcessReceive → ProcessHeartBeat → ProcessReceivedMessage → PRpcState.Update

组件还会把通道事件转发到事件总线：NetworkConnectedEventArgs / NetworkClosedEventArgs{Channel, Reason, ErrorCode} / NetworkMissHeartBeatEventArgs / NetworkErrorEventArgs（没有独立的 "Disconnected" 事件，断开即 Closed）。

3 INetworkChannelHelper — 编解码的唯一扩展点

public interface INetworkChannelHelper
{
    void Initialize(INetworkChannel networkChannel);   // DefaultNetworkChannelHelper：反射扫描全部 IPacketHandler 自动注册
    void Shutdown();
    void PrepareForConnecting();
    bool SendHeartBeat();                              // 心跳包由 helper 决定（IHeartBeatMessage）
    bool SerializePacketHeader<T>(T msg, MemoryStream dest, out byte[] body);  //包头
    bool SerializePacketBody(byte[] body, MemoryStream dest);                   // 包体
    bool DeserializePacketHeader(byte[] source);
    bool DeserializePacketBody(byte[] source, int messageId, out MessageObject msg);
}
// 默认实现 DefaultNetworkChannelHelper 还提供 SetChannelSerializer(IMessageSerializer)，
// 须在 Initialize 之前调用（protobuf-net / 自定义序列化器在此接入）

配套默认管线类：DefaultPacketSendHeaderHandler / DefaultPacketSendBodyHandler / DefaultPacketReceiveHeaderHandler / DefaultPacketReceiveBodyHandler / BasePacketHeartBeatHandler / DefaultMessageSerializer。消息基类体系在 Runtime/Network/Base/：MessageObject、IRequestMessage / IResponseMessage / INotifyMessage / IHeartBeatMessage。接收分发不走接口回调——由 ProtoMessageHandler.GetHandlers(msgType) 按 [MessageHandler] / [MessageTypeHandler] 特性反射注册的处理器在主线程 Update 消费队列时逐个 Invoke。

4 心跳机制（源码级）

private void ProcessHeartBeat(float realElapseSeconds)
{
    if (PHeartBeatInterval > 0f)
    {
        lock (PHeartBeatState)
        {
            PHeartBeatState.HeartBeatElapseSeconds += realElapseSeconds;
            if (PHeartBeatState.HeartBeatElapseSeconds >= PHeartBeatInterval)
            {
                sendHeartBeat = true;                       // 到点：发心跳
                PHeartBeatState.HeartBeatElapseSeconds = 0;
                PHeartBeatState.MissHeartBeatCount++;       // 同时丢跳计数 +1
            }
            if (sendHeartBeat && PFocusHeartbeat)
                if (PNetworkChannelHelper.SendHeartBeat()) return;   // 发出即认为本回合健康
            if (PHeartBeatState.MissHeartBeatCount > MissHeartBeatCountByClose)
                shouldClose = true;
        }
        if (shouldClose)
            Close(NetworkCloseReason.MissHeartBeat, (ushort)NetworkErrorCode.MissHeartBeatError);
    }
}
要点：收到任意数据包会重置计时（ResetHeartBeatElapseSecondsWhenReceivePacket）；MissHeartBeatCount 超阈值自动断开并广播 NetworkMissHeartBeatEventArgs；没有自动重连——重连由上层订阅 NetworkClosedEventArgs 自行处理

5 异步 RPC：Call<TResult>

Send 是即发即弃；Call<TResult>(req) 走 PRpcState：请求带序列号，收到匹配的 IResponseMessage 时 TryReply 完成 Task；超时（NetworkOptions.RpcTimeout，默认 5000ms）走 SetRPCErrorHandler 回调。RPC 的开始/结束/错误码三类 handler 都可挂。

// 消息分发的推荐写法：特性驱动，主线程执行
[MessageHandler(typeof(LoginResp))]
public sealed class LoginRespHandler : MessageHandler<LoginResp>
{
    public override void Handle(INetworkChannel channel, LoginResp message) { /* 更新 UI/状态 */ }
}

7 双端协议约定（Protobuf/）

Protobuf/proto/module_demo.proto（模块 10）——客户端 NetworkComponent 与服务端 SuperSocket(protobuf-net) 共用一份 proto3；生成工具（GameFrameX.Tools proto gen）双端各自产出 C#（接入属于后续基建，当前仓库放置协议与约定）：

syntax = "proto3";
package game.demo;
option csharp_namespace = "GameFrameY.Proto.Demo";

message HeartbeatReq  { int64 client_time = 1; }         // ID = (10 << 16) + 1
message HeartbeatResp { int64 client_time = 1; int64 server_time = 2; }
message LoginReq  { string account = 1; string token = 2; }
message LoginResp { int32 code = 1; int64 player_id = 2; string nickname = 3; }
message NoticeNotify { string content = 1; }             // 服务器推送
约定速记
  • 命名：请求 XxxReq / 响应 XxxResp / 推送 XxxNotify；一个功能模块一个 module_xxx.proto。
  • 消息 ID = (moduleId << 16) + seqId；demo 模块取 10，正式模块从 100 起（服务端 MinModuleId=10 / MaxModuleId=9999 分片校验）。
  • 字段编号 1~799 业务使用，800+ 预留框架。
